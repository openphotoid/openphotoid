### License red flags (verbatim findings)

- **RMBG-1.4**: "released under a Creative Commons license for non-commercial use… Commercial use is subject to a commercial agreement with BRIA." **Do not ship.** (rembg lists `bria-rmbg` but that doesn't change the weights license.)
- **RMBG-2.0**: "CC BY-NC 4.0… Commercial use is subject to a commercial agreement with BRIA." **Do not ship.** Note the irony: it's BiRefNet architecture — plain BiRefNet weights are MIT and nearly as good.
- **MatAnyone**: NTU S-Lab License 1.0 → non-commercial.
- **BEN2**: HF model card license tag is **MIT** (verify the LICENSE file at download time; PramaLLC monetizes via a separate closed "commercial model" — the released BEN2_Base is MIT).
- General caveat that applies ecosystem-wide: permissively-licensed weights trained on research-restricted datasets (DIS5K terms, P3M-10k, etc.) carry residual dataset-terms risk; industry practice (rembg, imgly, HivisionIDPhotos) treats the released weight license as governing.

## B. Matting refinement

| Approach | License | Trimap? | Notes |
|---|---|---|---|
| **pymatting** (closed-form, KNN, learning-based, large-kernel, random-walk, shared-sampling + closed-form & fast multi-level **foreground estimation**) | **MIT** | Yes (auto-generated from mask) | This is exactly what rembg's `-a` alpha-matting flag uses: erode/dilate mask → trimap → closed-form matting → foreground estimate. Pure numpy/scipy math — very portable to Rust. https://github.com/pymatting/pymatting |
| **FBA Matting** | Code MIT; **weights: Adobe Deep Image Matting Dataset License — "only … for noncommercial purposes"** (quoted from repo) | Yes | Best classical trimap quality, but weights are unusable commercially. https://github.com/MarcoForte/FBA_Matting |
| **ViTMatte** | **MIT** (code) | Yes | SOTA trimap matting (SAD 20.33 Comp-1k). **Caveat:** released checkpoints are trained on Composition-1k (Adobe DIM data) — same dataset taint as FBA; retraining needed for clean commercial weights. No official ONNX (HF `transformers` port exists → exportable). https://github.com/hustvl/ViTMatte |
| **Guided filter edge refinement** | OpenCV ximgproc `guidedFilter` (Apache-2.0); algorithm is He et al., patent-free classical method | No | The pragmatic PhotoRoom-style trick: run segmentation at 1024, upscale alpha to full res guided by the original RGB. Cheap (ms), CPU-friendly, easy to reimplement in Rust (~100 lines with integral images). |
| **Trimap-free strategy (recommended)** | — | — | Modern pipelines skip trimaps: BiRefNet-matting/BEN2 output soft alpha directly; then (1) guided-filter upsample to original resolution, (2) optional pymatting-style closed-form pass only in the uncertain band (0<α<1 dilated), (3) foreground color estimation (pymatting fast multi-level, MIT) to kill background color fringing before compositing on new backgrounds. |

## Recommendations

**Segmentation/matting stack (all commercial-clean):**
1. **Primary quality model: BiRefNet (MIT)** — use **BiRefNet-portrait or HR-matting** for people, **general** for objects; official ONNX exists. On CPU it's seconds-per-image, so gate it as "high quality" mode and enable GPU EPs (DirectML on Windows, CoreML on macOS) via ort.
2. **Fast/preview + batch default: BiRefNet-lite (MIT, ~180MB / fp16 90MB)**, or **MODNet (Apache-2.0, 25MB)** for realtime preview and low-end CPUs. HivisionIDPhotos' `hivision_modnet` (Apache-2.0) specifically for ID-photo solid-background output.
3. **Alternative/AB-test: BEN2 (MIT)** — strong hair claims; verify license file at fetch time.
4. **Refinement:** guided-filter alpha upsampling to full resolution + Rust port of pymatting closed-form in the uncertainty band + pymatting-style foreground estimation before background replacement. Avoid FBA/ViTMatte released weights (Adobe-DIM non-commercial taint).
5. **Excluded:** RMBG-1.4/2.0 (BRIA non-commercial), MatAnyone (S-Lab), insightface weights, CelebAMask-HQ-trained face parsing.
6. Optional interactive "click to select subject": **MobileSAM/SAM2-tiny (Apache-2.0)** feeding its mask into the matting refiner.

**Face stack:** YuNet ONNX (MIT, ~0.2MB, 5 landmarks) for detection/roll-alignment + MediaPipe Face Landmarker converted to ONNX (Apache-2.0) for eyes-open/head-pose/compliance; port HivisionIDPhotos' Apache-2.0 crop-spec + layout-sheet logic.

**Runtime:** ort (ONNX Runtime) — every recommended model is available or exportable as ONNX; ships fp16/int8 variants to hit a small default download (~25–90MB) with optional "HQ pack" (~0.5–1GB).
